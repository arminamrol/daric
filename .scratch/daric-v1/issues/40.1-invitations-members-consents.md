# 40.1: Invitations, Members and Consents

**What to build:** An Owner invites a partner or accountant by email or link with a role, can change or revoke it, and every Consent is recorded and revocable.

**Blocked by:** 26, 40

**Status:** done

- [x] Invitations API: create (email + copyable link), accept (requires verified email), revoke, expire
- [x] Members list, role change and removal following the role matrix in the plan
- [x] user_consents table and API; `workspace_sharing` Consent recorded on accept; revocation takes effect immediately
- [x] Audit log entries for invitations and role changes; audit viewer for Owner
- [x] Web screens for members, invitations and consents
- [x] HTTP tests for the role matrix
- [x] Creating an Invitation requires the Owner's sharing Entitlement (Plus); a Free Owner sees the paywall instead (ADR-0008)
- [x] Accepting needs no Plan; the Member's own device limit applies

## Comments

Notes for later tickets:

- Tables (migration 0018): `invitations` (Workspace-scoped, RLS; `daric_app` may SELECT/INSERT/UPDATE, never DELETE: spent rows stay as history) and `user_consents` (`workspace_id` nullable, `set null` when the Workspace goes; RLS with SELECT/UPDATE for `daric_app` so removing a Member revokes their Consent in the same scoped transaction). At most one live Consent per User, Workspace and purpose (partial unique index on `revoked_at IS NULL`). Both are left out of the data export, like audit logs.
- Role matrix is `rolesAssignableBy`, `mayManageMember` and `mayChangeRole` in `packages/core/src/api/member.ts`: the Owner gives Admin/Member/Viewer and manages everyone else; an Admin gives and manages only Members and Viewers. Nobody becomes Owner this way; transferring ownership is 40.2's business. The Owner cannot leave (403).
- Invitations: `POST/GET /v1/workspaces/:wsId/invitations`, `POST …/:id/revoke` (Admin+). The email is optional: with one, the link is mailed (in the inviter's language) and only a User with that verified email may accept; without one, anyone with a verified email may accept it once. Only the token's SHA-256 is stored, so the link is in the create answer only. 7 days (`INVITATION_TTL_DAYS`). One pending Invitation per email; an email that is already a Member gets 409. Status (PENDING/ACCEPTED/REVOKED/EXPIRED) is worked out on read.
- `POST /v1/invitations/preview` and `/accept` take the token in the body and run on the owner connection (not a Member yet). Accept refuses with 403 `reason: EMAIL_NOT_VERIFIED | EMAIL_MISMATCH`, 409 when already a Member, 400 for a spent link. It records the `WORKSPACE_SHARING` Consent (policy version in `consentPolicyVersions`, core) and audits `invitation.accept` + `consent.grant`.
- Sharing is the Owner's Entitlement: creating answers 402 when `entitlementsOf(owner).shareWorkspace` is false, whoever (Owner or Admin) sends it, and so does accepting if the Owner lost it meanwhile. `GET …/invitations` returns `sharingAllowed` so the web shows the paywall to Admins too. The accepting User needs no Plan; nothing else here touches devices, so 41 applies the Member's own device limit as for any login. 43 suspends Members of a lapsed Owner; this ticket only removes, it never suspends.
- Members: `GET /v1/workspaces/:wsId/members` (any Member), `PATCH …/:memberId {role}` (Admin+, matrix), `DELETE …/:memberId` (remove by matrix, or leave on one's own). `endSharing()` (`modules/members/sharing.ts`) revokes the Consent, audits, then deletes the membership last, because once it is gone RLS refuses further writes in that scope.
- Consents: `GET /v1/me/consents` (newest first, revoked included), `POST /v1/me/consents/:id/revoke` (owner connection). Revoking `WORKSPACE_SHARING` leaves the Workspace at once (`member.leave`). 40.3 adds `AI_ANALYSIS` to `consentPurposes` (and the `consent_purpose` enum).
- Audit: actions now live in core (`auditActions`); new ones go at the end and need `audit.action.*` messages. `GET /v1/workspaces/:wsId/audit?before=&limit=` is Owner only, newest first by `(created_at, id)`, with the actor's email and without IP or user agent. Rows of one transaction share `created_at`, so order by id within it.
- `afterScopedCommit(fn)` (`db/scope.ts`) runs `fn` after a Workspace-scoped request commits; Invitation mail uses it.
- Web: `/settings/members` (Members, Invitations with copy-once link, paywall), `/settings/consents`, `/settings/audit` (Owner), `/invitation?token=` (signed in or out; a signed-out visitor's token waits in `sessionStorage` and login/sign-up return there). A User in more than one Workspace now gets a Workspace switcher in the header (`currentWorkspace` in `auth/session.tsx`, localStorage, cleared on logout); `useSignedIn().workspace` follows it. Mobile still shows `workspaces[0]` and has no sharing screens.
- The audit page shows dates only; core's formatters have no time of day yet.
