# Entitlements are decided on the server; Plus is prepaid through a web checkout

What a User may do (number of Signed-in Devices, sharing a Workspace, AI analyses) is an Entitlement computed by the API from the User's Subscription; clients only display it and never decide. The Subscription belongs to the User, not the Workspace: sharing a Workspace is the Owner's Entitlement, and each Member's device limit comes from the Member's own Plan. When `BILLING_ENABLED` is false (the self-host default) every Entitlement is unlimited.

Plus is prepaid for 1–12 months chosen by the user, priced by the server from config with tiered discounts, and a purchase extends from the current expiry. There is no auto-renew, because card-on-file recurring billing is effectively unavailable in Iran; the user is reminded before expiry instead. Payment always happens on the web through a `PaymentProvider` interface (Zarinpal first, a fake in tests); mobile apps open the browser and return by deep link, and never use store in-app billing. Because Cafe Bazaar and Myket may require their own billing for digital goods, the in-app purchase link is controlled by a server-side `PAYMENT_LINK_MODE` (`external` | `info` | `none`) so a store build can hide it without a release.

When a Subscription ends there is a 7-day Grace Period; afterwards only the most recently active Signed-in Device stays logged in, Members of the Owner's shared Workspaces are suspended (not removed), and AI stops while its history is kept. Financial data is never deleted for non-payment, and resubscribing restores everything.
